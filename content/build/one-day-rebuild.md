这一天开始时站里只有两篇文章，结束时它有了名字、五个板块、两条每天自动运行的发布流水线，和一个真正能用的工具。记一下都做了些什么，以及踩了哪些坑。

## 一、先想清楚为什么要这个名字

原来的名字「海边小屋」只解决了一件事——私人空间。它说得清「这是谁的博客」，说不清「进来能读到什么」。内容攒到第二篇就开始别扭：写 AI 的文章和一封随笔躺在同一个列表里，读者只能靠翻。

于是先定了五个板块，再定名字：

- **AI 前哨** — 每天收集、总结 AI 前沿信息
- **灵光一现** — GitHub 上值得看的项目，以及怎么复刻
- **建站之路** — 这个站本身是怎么长出来的
- **工具箱** — 能直接用的小工具
- **趣味天地** — 测评、赛博算命这些不严肃的东西

名字取「蔚来实验室」：五条线都还只是实验，谈不上成熟。顺带承认一个副作用——它和某家汽车公司同音，搜索词大概率会撞车。权衡之后还是留下：先有内容，再谈搜索。

板块落地时有个细节值得记：旧的 `/posts/...` 已经被收录过一次，不能让它变成 404。Hugo 的 `aliases` 正好解决这件事——给迁移后的文章和新板块首页写上旧地址，构建时会生成一个 meta-refresh 页面，读者无感，搜索引擎也能跟着走。

```toml
# content/build/_index.md
aliases: ["/posts/"]
```

## 二、页脚那句「x 人在线」

需求很小：页脚加一句「现在有几个人在看」。做法上有两条路——塞个第三方统计脚本，或者自己算。

第三方脚本会拖慢首屏、也会把访客数据给别人，于是选了自算：站里原本就有一个记阅读数的 Python 小服务，顺手加一个 180 秒滑动窗口的内存字典。

- 访客每次访问任意页面，`/api/online?beat=1` 打一个心跳，服务端记下 IP 和时间戳
- 返回当前窗口内的独立 IP 数
- 页脚每 60 秒刷一次，页面切到后台就停

好处是「在线人数」这个词终于名副其实——它统计的是浏览器标签还开着的人，不是「当日 UV」。代价是单实例内存态，重启即清零，但一个个人站并不需要更严肃的方案。

## 三、AI 前哨：每天凌晨一点自动发一篇

这是这天最花功夫的部分。目标是：整理日常阅读的 AI 信息流，每天凌晨 1 点自动成文并发布，不用人管。

链条是 systemd timer → 抓取脚本 → LLM 总结 → 写 Markdown → git 提交推送 → Hugo 构建 → 切软链 → 清缓存。整条链路在服务器上跑，本地不用开机。

**信息源**选了媒体 RSS（量子位、TechCrunch AI、The Verge AI）、Hacker News 的 Algolia 接口、arXiv 的 cs.AI / cs.CL / cs.LG，以及 GitHub 上新近冒头的 AI 仓库。抓回来先按「权重 + 新鲜度 + 关键词」打分，再按板块配额挑出二十来条——给 arXiv 和 GitHub 设了保底，否则中文快讯会把论文全挤掉。

**踩得最惨的一个坑**：第一版上线，文章发出来了，正文是空的——整篇只有 184 字节，一个标题下面什么都没有。

排查发现，用的模型是推理型的，响应里先有一段 `reasoning_content` 再才是正文，而 `max_tokens` 是**把推理 token 一起算进去的**。素材一多，模型在「想」的阶段就把额度用光，正文被截断成空字符串。接口不报错，`finish_reason` 也不会明确告诉你「我话没说完」。

于是加了两道保险：

```python
# 1. 额度给够
"max_tokens": 12000

# 2. 正文太短就当失败，直接降级成纯聚合版
if len(content) < 200:
    raise ValueError(f"LLM 正文过短（finish={finish}, content_len={len(content)}）")
```

第二条比第一条重要：**失败要响**。一个静默产出空文章的流水线，比一个报错的流水线危险得多——你不会去看它，直到某天发现首页挂着三篇空白。

重新跑之后是 24 条、四个板块（今日看点 / 媒体动态 / 论文速览 / 开源热门），七千多字节，正常。

## 四、灵光一现：GitHub Trending 的每日点评

有了日报的经验，第二条流水线快得多：每天 01:35 抓 GitHub Trending 当日榜前十，逐个拉 README，让模型写一段趋势观察，再给每个仓库写「是什么、能干嘛、适合谁」。

两个必须记住的细节：

1. **抓 GitHub 必须带浏览器 User-Agent**。用默认 UA 拿到的是简化页，`<article>` 结构直接消失，解析出来是零个仓库。
2. **README 要截断、要剔代码块**。不剔的话模型会把大段安装命令当成项目描述复述一遍；四千字符足够讲清一个项目。

失败时同样降级成纯列表（语言、星数、今日新增），保证「每天一定有一篇」。

## 五、工具箱：把图片变成拼豆图纸

五板块里「工具箱」最容易做成空壳——放一堆链接，点进去还是别人的站。所以第一个工具自己写：**图片转拼豆图纸**。

需求很具体：给一张图，输出带网格和色号的图纸，再给一份「哪个色号要几颗」的清单。去 GitHub 上找了一圈，有现成项目，但要么是命令行工具、要么得部署后端。而这是一个纯静态站，没有后端可用——那就全部放到浏览器里跑。

算法是自己重写的简化版，四步：

1. **取样**：把图缩成「W × H」个格子，每格取面积加权的平均色；处理透明和纯白背景（超过四分之三的格子是白的就留空，不用铺满整板）
2. **压色**：k-means++ 把整张图的颜色聚成 8～32 个主色，控制「最多用色」——颜色越少越好买、越好拼
3. **映射**：用 redmean 加权距离找最近的 MARD 色号（人眼对绿色最敏感，所以绿色通道权重最高）；要照片效果就换成 Floyd–Steinberg 抖动
4. **去噪**：把孤立的单颗豆子并进周围颜色，省豆子也省眼睛

色板用了 MIT 授权项目的 MARD 291 色——国内最好买的体系。三个开源项目里，有两个没有 license，数据一律没用。

效果是这样的量级：一张 96×96 的测试图，32 格宽出 784 颗豆、13 个色号；开抖动 40 格宽出 1600 颗、79 个色号。图片全程不出浏览器。

## 六、这天踩的坑，攒成一张表

| 现象 | 原因 | 解法 |
| --- | --- | --- |
| 文章发出来正文是空的 | 推理模型的 `max_tokens` 含推理 token，额度被「想」用完 | 额度调大 + 正文过短直接抛错降级 |
| Trending 解析出 0 个仓库 | 默认 UA 拿到简化页 | 带浏览器 UA |
| 抓到的 RSS 是 HTML 页面 | 那个源的官方 RSS 早已下线 | 换源，或走 RSSHub |
| 定时任务显示的时间差 8 小时 | 服务器是 UTC，`OnCalendar` 要显式写时区 | `*-*-* 01:00:00 Asia/Shanghai` |
| 清缓存报 `Invalid request headers` | token 复制时带了引号 | 配置文件里不要引号，解析器也不该指望它 |
| 一行 Python 命令跑不动 | PowerShell 里中文和引号互相打架 | 一律写成 `.py` 文件再执行 |

## 收尾

一天下来最大的感受不是「做了多少功能」，而是**自动化最贵的部分不是写代码，而是让它失败时能被发现**。空正文那次如果没顺手加个「正文少于 200 字就报错」，大概率要等几天后翻首页才会发现。

下一步想做的：图纸能记住上次的设置、导出可打印的分页版，以及工具箱里再补两三个真正会用到的工具。
